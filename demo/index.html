01 / THE IDEA

Good analytics starts
before the dashboard.

Source data needs a reliable path from arrival to analysis. Medallion architecture makes that path explicit.

Bronze preserves the inputs. Silver cleans and deduplicates them. Gold applies business rules and produces useful aggregates. This project connects those ideas to executable notebooks, data-quality checks and a reproducible reference runner.

    The full project, mapped out.

    Source → Bronze → Silver → Gold

    The Databricks path ingests the source, creates Delta layers, applies transformations and quality checks, and can export aggregates to Snowflake. Kafka provides a separate streaming ingestion path.

    Browse the notebooks ↗

    Know what runs where.

    This browser reads precomputed CSV and JSON outputs. The local Python runner computes those outputs with SQLite. Spark, Delta, Kafka and Snowflake run separately with their own configuration.

    Read the architecture notes ↗

    How to run the broader Databricks workflow
    1. Use a Databricks workspace with Spark, Delta Lake and a dedicated demo Unity Catalog Volume.
    2. Upload the committed customers and orders JSON. Set the notebook base_path widgets to that Volume.
    3. Run schema_setup, bronze_pipeline, silver_pipeline and gold_pipeline in order.
    4. Run data_quality_checks and reconciliation_pipeline to inspect the results.
    5. Configure the Kafka broker and consumer widgets for streaming, or the Snowflake connector and warehouse for exports.

    Use a dedicated demo Volume: some notebooks overwrite their output paths. Follow the repository README before running them.

    Reference behaviour and current limitations

    The local reference uses SQLite and keeps the first source row for duplicate order IDs. The Spark notebooks use distributed deduplication, which can retain a different row when duplicates conflict. The code examples above illustrate the reference logic.

    No throughput, latency, production availability, anomaly-detection accuracy or live streaming reliability has been benchmarked in this showcase. The synthetic dataset is a learning fixture, not a business dataset.
